## 🧭 How I approach engineering

I care about more than making the code work.

For non-trivial systems I usually think about:

- What are the invariants?
- What happens under concurrency?
- Where should the transaction boundary be?
- What happens when something fails halfway through?
- How does this behave under load?
- How do we observe it in production?
- How can we roll it out safely?
- How do we test the failure paths, not only the happy path?

I enjoy architecture and system design, but I remain hands-on with
implementation, debugging, code review and production support.
